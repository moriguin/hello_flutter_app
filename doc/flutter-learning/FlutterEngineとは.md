# Flutter Engine とは

Flutter Engine は、Flutter アプリケーションの基盤となる低レベルのレンダリングエンジンです。主に C++で書かれており、Flutter の心臓部と言える存在です。

## 主な役割

### グラフィックスレンダリング

- Skia というグラフィックスライブラリを使用して、画面に描画を行います
- iOS、Android、Web、デスクトップなど、すべてのプラットフォームで一貫した見た目を実現

### Dart ランタイムのホスティング

- Dart で書かれたアプリコードを実行する環境を提供
- JIT コンパイル(開発時)と AOT コンパイル(リリース時)の両方をサポート

### プラットフォーム連携

- ネイティブプラットフォーム(iOS/Android)と Dart コード間の通信を仲介
- Platform Channels を通じて、カメラや GPS などのネイティブ機能にアクセス

## Flutter アーキテクチャの中での位置づけ

```
[Flutter Framework (Dart)] ← 私たちが書くコード
        ↓
[Flutter Engine (C++)]     ← ここ!
        ↓
[プラットフォーム (iOS/Android/Web等)]
```

Riverpod や Isar などは、Flutter Framework レイヤーで動作していて、その下で Flutter Engine が実際の描画や Dart コードの実行を担当しています。

## JVM との比較

Flutter Engine は「Dart ランタイムを提供する」という点で JVM に似ていますが、いくつかの重要な違いがあります。

### 似ているところ

- **言語ランタイム**: JVM が Java バイトコードを実行するように、Flutter Engine は Dart コードを実行
- **プラットフォーム抽象化**: どちらも OS 固有の処理を抽象化して、同じコードが異なるプラットフォームで動く
- **メモリ管理**: ガベージコレクションを含むメモリ管理を担当

### 違うところ

**UI レンダリングが含まれる**

- JVM は UI レンダリングを直接担当しない（Swing や JavaFX は別のレイヤー）
- Flutter Engine は**Skia を使った描画エンジンも内包**しているので、UI の描画まで一手に担う

**コンパイル戦略**

- JVM: 主に JIT（実行時コンパイル）
- Flutter Engine: 開発時は JIT、リリース時は**AOT**（事前コンパイル）でネイティブコードに変換してパフォーマンス向上

**スタンドアロン**

- JVM はデバイスにインストールされた共有ランタイム（場合による）
- Flutter Engine は**各アプリにバンドル**されるので、アプリサイズが大きくなる

## まとめ

Flutter Engine は「**JVM + 専用グラフィックスエンジン**」が一体化したものと理解するとわかりやすいです。

開発者として普段は意識しませんが、アプリのパフォーマンスや描画の仕組みを理解する上で重要なコンポーネントです。
