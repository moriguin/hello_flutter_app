# コード生成と import/part の理解ガイド

このプロジェクトで使われているコード生成の仕組みと、`import` と `part` の違いを解説します。

---

## コード生成コマンド

```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

このコマンドは、**コード生成が必要なファイルを作成・編集した時**に実行します。

---

## 1. コード生成の仕組み

このプロジェクトでは **3 つのライブラリ** がコード生成を行っています：

### ① Riverpod (riverpod_generator)

**何を生成するか**: プロバイダーの実装コード

```dart
// あなたが書くコード (timeline_provider.dart)
import 'package:riverpod_annotation/riverpod_annotation.dart';

part 'timeline_provider.g.dart';  // ← 生成されるファイル

@riverpod
class Timeline extends _$Timeline {  // ← _$Timeline は生成される
  @override
  Future<TimelineState> build() async {
    // ...
  }
}
```

**生成されるもの** (`timeline_provider.g.dart`):

```dart
// 自動生成されたコード
mixin _$Timeline on AutoDisposeAsyncNotifier<TimelineState> {
  // Riverpodの内部実装
}

final timelineProvider = AutoDisposeAsyncNotifierProvider<Timeline, TimelineState>.internal(
  Timeline.new,
  name: r'timelineProvider',
  // ...
);
```

**なぜ必要？**: Riverpod のボイラープレート（定型コード）を自動生成して、あなたはビジネスロジックだけに集中できる

---

### ② Isar (isar_generator)

**何を生成するか**: データベーススキーマとアクセスメソッド

```dart
// あなたが書くコード (mood_entry_model.dart)
import 'package:isar/isar.dart';

part 'mood_entry_model.g.dart';  // ← 生成されるファイル

@collection
class MoodEntryModel {
  Id id = Isar.autoIncrement;

  @Index()
  late DateTime recordedAt;  // ← @Index() で索引を生成

  late int emotionLevel;
}
```

**生成されるもの** (`mood_entry_model.g.dart`):

```dart
// 自動生成されたコード
const MoodEntryModelSchema = CollectionSchema(
  name: r'MoodEntryModel',
  id: -123456789,
  properties: {
    r'emotionLevel': PropertySchema(id: 0, name: r'emotionLevel', type: IsarType.long),
    r'recordedAt': PropertySchema(id: 1, name: r'recordedAt', type: IsarType.dateTime),
    // ...
  },
  indexes: {
    r'recordedAt': IndexSchema(id: 123, name: r'recordedAt', unique: false, replace: false, properties: [
      IndexPropertySchema(name: r'recordedAt', type: IndexType.value, caseSensitive: false),
    ]),
  },
  // データベースへの読み書きメソッド（serialize/deserialize等）
);
```

**なぜ必要？**: データベーススキーマ定義と、高速なバイナリシリアライゼーションを自動生成

---

### ③ Mockito (build_runner + mockito)

**何を生成するか**: テスト用のモッククラス

```dart
// あなたが書くコード (timeline_provider_test.dart)
import 'package:mockito/annotations.dart';

@GenerateMocks([MoodEntryRepository])  // ← これでモックを指定
import 'timeline_provider_test.mocks.dart';  // ← 生成されるファイル

void main() {
  late MockMoodEntryRepository mockRepository;  // ← 生成されたクラス
  // ...
}
```

**生成されるもの** (`timeline_provider_test.mocks.dart`):

```dart
// 自動生成されたコード
class MockMoodEntryRepository extends _i1.Mock implements _i2.MoodEntryRepository {
  MockMoodEntryRepository() {
    _i1.throwOnMissingStub(this);
  }

  @override

    required _i5.DateTime? start,
    required _i5.DateTime? end,
  }) =>
      (super.noSuchMethod(
        Invocation.method(#getEntriesByDateRange, [], {#start: start, #end: end}),
        returnValue: _i3.Future<List<_i4.MoodEntry>>.value(<_i4.MoodEntry>[]),
      ) as _i3.Future<List<_i4.MoodEntry>>);

  // 他のメソッドも自動生成
}
```

**なぜ必要？**: テストで使うモッククラスを手動で書くのは面倒なので自動生成

## 2. `import` vs `part` の違い

### `import` - 通常のインポート

```dart
import 'package:flutter/material.dart';
import 'package:riverpod_annotation/riverpod_annotation.dart';
import '../domain/models/day_group.dart';
```

- **別のライブラリやファイルを読み込む**
- お互いに独立したファイル
- public な要素（クラス、関数等）のみアクセス可能
- プライベート（\_で始まる）にはアクセスできない

### `part` - ファイルの分割

```dart
// timeline_provider.dart (親ファイル)
part 'timeline_provider.g.dart';  // ← これは「このファイルの一部」という宣言

@riverpod
class Timeline extends _$Timeline { /* ... */ }
```

```dart
// timeline_provider.g.dart (子ファイル)
part of 'timeline_provider.dart';  // ← 「timeline_provider.dartの一部です」

mixin _$Timeline { /* ... */ }  // ← プライベート（_）でもアクセス可能！
```

**特徴**:

- **同一ファイルとして扱われる**（論理的には 1 つのファイル）
- プライベートメンバー（`_$Timeline`）にもアクセス可能
- スコープを共有する
- コード生成で使われることが多い

### なぜ `part` を使うのか？

コード生成では、**あなたのクラスのプライベートな実装（`_$Timeline`など）にアクセスする必要がある**ため、`import` では不十分で `part` が必要になります。

## コード生成が必要なケース

### 1. Riverpod のプロバイダーを作成・編集した時

```dart
@riverpod
class Timeline extends _$Timeline {
  // ...
}
```

→ `timeline_provider.g.dart` を生成する必要がある

### 2. Isar のモデル（@collection）を作成・編集した時

```dart
@collection
class MoodEntryModel {
  // ...
}
```

→ `mood_entry_model.g.dart` を生成する必要がある

### 3. その他のコード生成アノテーションを使った時

- `@freezed`（freezed パッケージ）
- `@JsonSerializable`（json_serializable パッケージ）など

---

## コマンドのフラグ

- `build`: コード生成を実行
- `--delete-conflicting-outputs`: 既存の `.g.dart` ファイルと競合する場合、古いファイルを削除して上書き

---

## 開発の Tips

### watch モードを使う

開発中は以下のコマンドを使うと、ファイル変更を監視して自動で再生成してくれます（便利！）：

```bash
flutter pub run build_runner watch
```

### 注意点

- **実行しないと**: コンパイルエラーになります（`part 'xxx.g.dart';` が見つからない）
- **生成ファイルは Git 管理しない**: `.gitignore` に `*.g.dart` を追加することもあるが、このプロジェクトではコミットしている

## まとめ表

### コード生成ライブラリ

| ライブラリ             | 何を生成？                                    | なぜ必要？           |
| ---------------------- | --------------------------------------------- | -------------------- |
| **riverpod_generator** | プロバイダーの実装コード（`_$Timeline` など） | ボイラープレート削減 |
| **isar_generator**     | DB スキーマ + CRUD メソッド                   | 高速な DB 操作コード |
| **mockito**            | テスト用モッククラス                          | テストコードの簡略化 |

### import vs part

| 構文       | 用途                              | スコープ           |
| ---------- | --------------------------------- | ------------------ |
| **import** | 別ファイル/ライブラリを読み込む   | public のみ        |
| **part**   | ファイルを分割（論理的には 1 つ） | private も含む全て |
